# Python 正式验证适配器修补（2026-09-23）

本轮修补 SBNO 试用暴露的接线错误：旧 Node 验证沙箱拒绝测试脚本启动 Python，12 次正式检查未执行 Python。原试用、冻结脚本、deadline、候选缺失和计量未知项均保持原样。本轮没有真实模型调用、新研究任务、外部认可或历史重评。

基线与本轮材料：`/workspace/research-python-verification-20260923T071002Z/`。开始时保存了工作树清单、既有差异和相关源码副本；工作树原有改动未重置或提交。最终改动清单、测试日志、实际宿主的 CAS／操作记录／产物和保全核验另存于此目录。

## 实施范围

增加显式 `manifest.verification.adapter: "python-script:1"`，旧 `node-test-tap:1` 保持原语义。新适配器的 `executable` 仍是可信 Node 控制器；新增的 `python`、`isolation` 对象由外部任务配置提供固定可执行文件路径和 SHA-256。发行与每次执行前核验身份，控制器再次核验 Python／隔离器。模型不填写这些身份。

每个冻结 Python 脚本对应 `expectedTests` 中一个命名检查；入口必须正常返回，失败应抛异常，`unittest` 可以用 `exit=False` 并断言 `wasSuccessful()`。不把脚本返回当成每条内部断言确已执行的证明，也不把通过脚本当成科学正确性证明。支持多个预先约定脚本，无新增累计实验或请求上限。验证单次期限仍来自 manifest，并受原任务绝对 deadline 约束。

修改留在 SDK research 验证／证据适配层与共用隔离源码接线；Core、agent loop、评审决策和外部认可接口没有修改。可选回应与 completion 没有新增门槛。

## Python 本身的隔离与清理

- 共用 Landlock ABI 6／seccomp 隔离器的维护源码位于 `packages/sdk-next/src/research/isolate.c`，现有 evaluation launcher 从该处编译。旧 evaluation 下的 C 文件保留原字节；新源码纳入运行版本身份。
- Python 使用干净环境、固定解释器、隔离启动参数和独立临时目录。可读范围是冻结候选及系统运行库；写入限于指定生成文件、私有临时目录和 `/dev/null`。不开放模型凭据、宿主存储或网络。当前目标配置为 Linux x64、系统 Python 与 **CPU** PyTorch，未验证 GPU 执行。
- 控制器预建精确输出文件以授权文件级写入；未被写入的占位文件会移除，不能冒充新产物。路径逃逸／符号链接检查和 replay 的前后保护检查仍在。
- 无网络子监督器保持在执行器的进程组内，接收取消；Python 位于可清理的子进程组，`--tree` 禁止其逃逸。正常结束、超时、取消均清理并回收派生进程，无须向内层开放 `/proc` 进程树读取。
- 为组合两层隔离，外层允许通过 `prctl` **追加** seccomp filter，并只允许设置 `SIGKILL` 父进程死亡信号；仍拒绝 `seccomp()`（含新通知 listener）、清除死亡信号和改成其他信号。追加 ALLOW filter 不能撤销既有限制；真实宿主测试执行了这项反例。内层额外以 seccomp ERRNO 拒绝 `connect`，优先于继承的外层 USER_NOTIF 网关 broker，避免 broker 注入已连接 socket 绕过内层 Landlock；测试目标包含宿主实际获准的网关端口。现有网关地址、Fast Open、进程内存及逃逸回归继续验证。

## 状态、反馈和证据

| 实际事件                               | 记录与处理                                                                                                                                               |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 解释器／隔离器未启动检查               | `unavailable`，说明启动或权限配置问题不能靠修改算法修复，保存原始日志                                                                                    |
| Python 检查运行并抛异常                | `failed`，保留 traceback、实际产物和候选身份，向 Researcher 返回失败证据后恢复授权工作                                                                   |
| 全部约定脚本正常完成                   | 仅在 replay、产物、身份及保护条件也满足时为 `passed`，随后可请求 advisory review 并明确提交                                                              |
| 提前退出／控制器协议缺失／监督清理异常 | `unavailable`，不把退出码零或 Python 打印的 TAP 当成通过                                                                                                 |
| 单次验证超时                           | 保留 Core 的真实失败 job；验证适配层根据 Core 已归档报告核验候选／策略／hash，并关联 `unavailable` 记录与部分输出，不把 job 改成 completed               |
| 主动取消                               | 保留 cancelled／interrupted job、不可完整化的 replay 和捕获到的输出，不制造成功验证                                                                      |
| 整个宿主到原 deadline                  | 外部启动器关闭 IPC 并清理进程；可能早于规范化验证报告写入。核查保留的临时产物、操作日志、清理状态和未知终态，不能延长 deadline 或推断 durable 合同已取消 |

Python 日志和可信控制器结果分开传输，前者不能直接冒充结果协议。Python 与被导入的候选仍共享语言运行时；这不是抵御恶意模块篡改所有断言的形式证明。候选、保护输入、策略及原始证据的机械身份校验独立成立，科学判断仍需独立审阅。

超时补记仅解析 Core 自己产生的固定错误及报告 hash，重新读取并校验归档、候选和 replay policy；未知错误不猜补报告。不修改旧报告或原操作账本，不新增自动恢复／重试流程。
