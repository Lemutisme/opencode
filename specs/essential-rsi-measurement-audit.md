# Essential RSI 与历史 R2：测量审计与下一轮识别设计

2026-10-08；只读复核既有结果，不启动模型、评分或新 cohort。

## 判断

**新版没有追平这组同题历史 R2 观测。负结果足够明确，值得立即改进；因果尚未识别不是拒绝改进的理由。**
但也不能把“更简洁的内核”或某个具体实现机制直接认定为全部 −5.98 pp 的原因。
应该从可见轨迹提出最小机制修复，再用同期匹配对照区分有效方法和无效复杂度。

本轮为 Luna / max、九个任务各两次；17 个有效评分，tig 第二次未知。历史 R2 每题只有一次。
本审计没有读取隐藏失败测试内容；只读现成分数、协议、时间及正式事件计数。

## 5. 对机制分析最有用的非分数证据

本轮 **proposal 0 / comparison 0 / adoption 0**；所有实际执行仍使用 seed method。
所以这是当前方法在 RSI-enabled runtime 中的表现，不是“已学习后继策略 vs incumbent”的实验。
也不能把有 checkpoint、更多测试或任意随机分差事后命名为已经完成了正式后继策略验证。

以 `deadline − 6h` 为 admission，最后一个 native fence 为求解结束代理，
18 个任务的 native 阶段只有 **25.6–55.5 分钟**；评分在其后可以继续消耗时间。
**本轮不是六小时求解预算耗尽。** 原始评分未知的 tig r2 也不是 deadline 用尽导致。

这使以下假设值得优先检查：模型是否在尚有可行动的不确定性时 submit；
是否没有保留足以选择下一次区分性实验的证据，因而把“基本实现/自测通过”当成“无需再探索”。
这些是待轨迹检验的机制假设，不是单靠 elapsed time 已经证实的原因。
六小时是 ceiling，不应改成强迫任务忙满六小时；真正完成的任务可以提早结束。

## 6. 最小同期识别设计：先恢复求解方法，再研究主动 RSI

以下是建议，不是已冻结协议，不授权启动。

### 第一阶段：只比较方法，不让 runtime 差异混进来

在相同新 runtime、scorer、rootfs、输入、模型 route/effort、资源和隔离下，冻结两个 fixed-policy 条件：

- **A：** 当前 seed。
- **B：** 最小证据驱动方法：行为面清单 → 保留可重放完整观测 → 按当前差异/未知选择区分性实验 → 修复共同原因 → 重放受影响回归。

B 借鉴 R2 的工作原则，不直接迁移其调度器，也不把 kernel 增大当作性能改进。
两条件使用相同提案权限/调度；本阶段固定 policy，不把外部写入 B 称作自主 RSI。
原始任务仍只有六小时绝对 deadline，无累计 provider/tool/request/金额上限，不以大有限数模拟 unlimited。

先作公开机制诊断可选 hexyl（稳定缺口、reference 满分）、eva（明显波动）、xh（最大缺口）：
固定重复次数、同期交错安排 A/B，明确这些任务是在本次结果后选择的开发诊断，不标成预注册确认。
两次重复已经显示波动；下一轮需在冻结前选择足够重复数，不在看到结果后逐步加到“刚好成功”。

除独立最终分数外，记录可解释过程量：

- 已覆盖、未解决的行为面；有效的最小差分样本及完整 stdout/stderr/exit code；
- 每个观察如何支持下一步行动；修复后的回归是否可重放；
- checkpoint 前后是否丢失当前未知；submit 时实际持有什么证据；
- wall time、请求/token 与工具使用全量记账，未知不补零。

这些过程量用于解释，不代替评分晋升规则；更多调用或更久工作本身不是成功。

### 第二阶段：显式发起方法改进任务，再独立验证

只有在第一阶段知道什么机制有效之后，才把“根据公开 development 轨迹生成一个后继方法”设为明确普通任务，
而非期待求解器偶然调用可选 propose。生成器不接触私有确认失败详情。
后继方法及其来源先冻结，再用独立的匹配运行比较 incumbent 与 successor；正式记录生成、比较、选择、接续各环节。

用于晋升的完整 development/confirmation、固定 repeats、full-pass 保护、安全与责任条件需另行冻结。
采用用户选择的 task-Pareto：按每题固定重复均值，无一题退步、至少一题严格提高；全 ties 不晋升，证据缺失不晋升。
若需要泛化结论，使用未用于本次诊断的新确认任务；不能把这九题重新命名成未见证据。
