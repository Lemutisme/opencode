## 勘误与实现边界

**计划评审。** `ResearchPlanning` 的材料显式标记 `phase: planning`、`candidateRole: pre_execution_background`。提示要求检查拟议方法、可行性和未来验证，说明 worker 尚无写入／任意执行权限；未来报告、生成产物尚未存在，本身不能阻断计划。背景中的实现缺陷仍须在计划中得到处理，缺失固定输入、矛盾约定、不可行方法和未覆盖的必要验证仍可阻断。固定 smoke tests 非穷尽时，应检查计划如何覆盖其余义务，不能无端要求改写受保护的 harness。

共享 reviewer instructions 在该阶段仅适用于拟议工作，最终交付评审继续要求已实现的内容和正式证据。`within_task` 与计划正确性分开：可在原约定内修正的方法错误可获 `changes_requested`，不必一概要求 Principal revision；真正改变外部协议或无法解释的固定输入仍需明确上提。

**公开数据。** `observationIDs[i]` 对应 `(a[i], b[i])` 这一对观测；`a` 和 `b` 是方法数组，非观测 ID。四个 ID 唯一且完整，train 为前两对、validation 为第三对、test 为第四对。`primaryIDs` 为全部四对，主问题保持固定方法下的描述性配对均值与两单位阈值，不是 held-out 泛化估计，不进行必需的拟合／选参。正式 `result.json` 的 `observations` 表示八个方法标量，同时保存观测 ID、主指标 ID 和 split。

split 约束任何可选探索的拟合／选参／独立评估，不替代主指标总体。公开任务明确辅助阈值比较使用固定候选，按选择集的 `rate(b,t)-rate(a,t)` 最大化选参，同分取较小阈值，然后在留出 test 上评估；该比较不拟合，因此不使用 train。其结果只能作为探索性诊断。

**P1 好坏配对。** 两侧都选择执行同一个辅助比较，候选、目标、tie 规则和报告范围相同，仅 `plan.method` 改变选参集合：好侧 validation，坏侧 test 且仍把同一 test 称为独立评估。共享阈值为 `[offset+6, offset+8]`：validation gains 为 `[1,0]`，正确选择的 test gain 为 `0`；坏侧在 test 的 `[0,1]` 中择优后报告 `1`。目标缺陷是辅助评估的独立性失效，并非固定 all-pair 主效应变坏。删去不必要的辅助分析也是合理修复，坏计划原样接受仍不正确。

**独立评分依据。** oracle 从冻结公开的配对数值独立计算主效应，核对正式产物的完整观测 ID、全部主指标 ID、split 及标量计数；不会用候选自行声明的子集自证。计划 rubric 同步区分尚未执行的计划、固定主指标和条件性的探索评估职责。两套变体的全部公开坐标及 P1 数值反例均有自动检查；节点测试实际生成的 R3 产物用于检验评分器对重标 ID、偷换总体／split、正负结论及数值错误的拒绝。

**引用协议。** 本轮保持 64 位 hash 的严格 schema 和 allowlist，不由控制器补字或修复模型报告。计划提示补充逐字复制允许引用及其语义的说明，并增加 63 位引用的拒绝回归。更换结构化引用协议留作独立设计事项，以免把协议变化混入本轮阶段／语料校准；旧格式失败不会改成成功。

## 本轮验证目标

1. P1 坏计划的首份完成报告定位辅助比较中的 test selection 泄漏，实际 gate 关闭。
2. P1 好计划获可用、在范围内的评审，不因缺少未来阶段的交付物被阻断，实际 gate 打开。
3. R3 经真实 worker 和 reviewer 完成计划、实现、正式 Node 实验及最终评审；独立核验全部四对数据得出一单位效应、未达到两单位阈值的正确负结果，检查报告、原始证据、控制说明和边界实现。

真实校准前先完成生产阶段回归、Responses 完整任务回归、默认确定性校准、两个受影响包的类型检查和独立实现／语料复核。实际运行配置另建目录冻结；所有尝试保留分母和原 deadline。以下记录实际结果，不能由本节的预期推定通过。

## 新发现与独立诊断

**成功实验后没有收尾。** 归档包含 26 个正式实验，均为 `passed`，全部绑定同一候选 `2f31057b26a63f54cf13c693ef60b3508dba8a36` 和同一 `result.json` 工件 `1b4d3f28864d5325ffe16274d0600085582be0915c9cefbd5bd7af4b6d2ef90c`。模型只写过一次 `report.json`，没有调用 `contract_report_ready`。第一轮成功反馈后读取工作区 `result.json` 失败，后续仍重复实验。

正式工件由隔离实验归档，不会写回 worker 的候选目录。26 份实验后提示都同时包含“请求 experiment 后停止”和“成功后调用 ready”，且附有明确的 `passed` 结果。生产工具策略允许 ready，没有合法 ready 请求被宿主拒绝的证据。工件访问方式和实验后的提示可能共同诱发循环，但当前轨迹不能分离它们与模型执行能力的影响，不能直接定性为 gate 故障或模型总体能力不足。

**公开引用规则与 oracle 不一致。** 候选报告的 `evidence` 使用“文件名＋括注”。公开 schema 仅要求非空字符串数组，任务没有规定必须使用裸文件名；既有 oracle 却用 `includes("data.json")`／`includes("result.json")` 精确检查。独立复核确认这是未公开的格式收紧。本轮诊断保留 `references: false`，不能据此单独判定科学结论或证据错误，更不能追溯改写本次结果。这个问题在运行前回归和审查中未被发现。

**数值负结果可核验，但交付不完整。** 独立审查者直接读取 hash 校验后的候选 tar 和原始实验工件，精确计算四对 `(10,11)`、`(12,13)`、`(14,15)`、`(16,17)`：两均值为 13 和 14，效应为 1，$1 < 2$，与报告的 `negative` 及原始结果的 `effect: 1` 一致。全部四个 ID、主指标总体、互斥 split 和八个标量计数一致；报告正确区分配对基线控制与未做的随机控制，没有声称普适因果结论。

主执行者另用既有隔离 candidate executor 检查 17 个空输入、相等边界和阈值输入，全部通过；候选没有加载进持有 oracle 的进程。诊断 `objective.json` 中结构、边界、数值、总体、结论、控制、因果字段均通过，引用项保留上述格式差异，主观项仍待评分。这只是对已归档材料的诊断，不替代完整 R3 的最终审查与独立正确性评级。
