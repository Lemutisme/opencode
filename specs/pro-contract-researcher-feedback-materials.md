# 反馈核查材料：第九轮归档离线诊断与最小去重

2026-09-22。证据目录：`/workspace/researcher-feedback-materials-20260922T024846Z`。这是材料表示的离线工程验证，不是第九轮重新评分或新真实校准。修改前 6,656 文件基线与第九轮冻结源码一致；既有工作树改动完整备份，未以 HEAD 替代。

主要问题已经定位：`prepareAdvisoryArchive` 把全部 run 状态展开到 `trajectory.archive.runs`，`observeAdvisory` 随后把整份材料送入单个反馈请求。每次持久化状态都重复携带任务约定、执行提示、计划等大字段。P1 坏有 146 个状态，R3 有 96 个，P1 好有 100 个；这不是同样数量的实验。此次只消除这些状态字段的精确重复，不压缩观点、不选择“重要”事件。

历史状态占正文约 65%–71%。P1 坏仅 `input` 的 8,292 bytes 就展开 146 次成为 1,210,632 bytes；`executionPrompt` 只有四种原值，却共占 1,133,530 bytes。R3 和 P1 好也各重复了同一约定 96／100 次。状态中的 `plan` 值分别占 379,721／212,181／225,805 bytes，包含计划及其审查状态；其 15／5／5 种不同值不是 15／5／5 版研究计划，不合并这些不同内容。

每份 `analysis.mjs` 仅 286 bytes，三份历史文件快照中的代码共 858 bytes；不能把整个状态历史的体积归因于研究代码。会话里保留原始提示、工具输入输出、文本及 provider 元数据。IPC journal 原流没有直接装入此请求（0 bytes）；操作账本、正式输出、交互中的重复提示等仍分别存在于上述组件。嵌套的代码／计划／输出分解不能再次加到父组件总数中。A/B 使用同一材料的独立请求是预定核查安排，未将其当作同一请求内部的冗余消除。

超限是 provider 返回的 `context_length_exceeded`，不是本地 16 MiB 传输限制触发。被冻结的本地 context 配置为 1,050,000，output 为 128,000，但服务端未给出该失败请求的 token 数或实际可用窗口；不能由 4.7 MB 推导精确 tokens。此处只报告已保存的 token 用量，没有估算或调用 tokenizer／模型接口。

## 最小修改

新增评测私有表示 `shared-run-fields:1`，仅用于新的 observation 反馈材料中的 `trajectory.archive.runs`。每条状态、每个字段、原始顺序全部保留。精确 JSON 内容相同、重复出现且至少 256 bytes 的字段共享一份完整原值；状态字段使用本请求内的引用。其余字段原值内联。256 bytes 仅决定表示方式，不是研究、次数或请求预算；若改写并不缩小材料，保留原形状。

完整值、内容 hash 及读取说明都在同一请求的 `contents` 中，核查者不必访问文件路径或额外工具。字段外包装区分“原值本身含有 ref”与宿主引用；离线恢复拒绝缺失、损坏或歧义引用，没有跨请求查询。共享只影响请求呈现，不合并事件、review job、计划版本或候选身份，不改变其归属。

接线仅在 `advisory-opinions.ts`。独立候选请求、旧正式评分、无候选终态分支、rubric、独立上下文和揭盲顺序都保持。宿主给新材料重新计算并保存 material hash；原始归档 hash 仍在 source 中。没有 Researcher 字段、回应／completion 要求、执行门槛、权限、deadline、累计上限或 Core／Constitution 变化。历史冻结副本不会采用此表示；未来真实批次仍需另行冻结源码。
